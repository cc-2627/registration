Set up a course

Your course's organization

Each course edition gets its own GitHub organization. Its students' teams and repositories live there, apart from everything else you have on GitHub. A free organization is enough.

Create it before anything else. The tokens in the next steps are made for this organization alone, and GitHub can only tie a token to an organization that already exists.

Create it on GitHub ↗

Use exactly this name when you create it. Already have one for this course? Just enter its name. The next step checks it exists, and that you own it.

The course repository's name

Students open their registration form in this repository. Keep the default unless you have a reason.

A token for setting up

A website can't make tokens or act on GitHub for you without one. So you make this one yourself on GitHub, with everything filled in, and paste it here. It's for setting up only.

How this token works

  • It reaches and nothing else. It's a fine-grained token whose resource owner is . GitHub fixes that one owner when the token is made. It can't touch your own repositories, or any other organization.
  • The page checks before using it. Classic tokens are refused, because they reach everything you can. The page then proves the token belongs to , with a request GitHub refuses without changing anything.
  • It goes only to GitHub. It stays in this tab's memory and is sent only to api.github.com. Nothing is saved, so closing the tab forgets it. There's no bedel server. The page's Content-Security-Policy (in its source) stops your browser from letting it connect anywhere else.
  • It lasts 7 days, and you can delete it the moment setup is done.

Rather not paste a token into a web page? Clone bedel and run ./scripts/setup.sh. It does the same with your gh login.

    The bot's token

    The bot is the set of GitHub Actions workflows in your course repository. They create teams and repositories and lock them at deadlines, so they need a token of their own, kept for the whole term.

    How the bot's token works

    • It reaches and nothing else. Like the setup token, it's fine-grained and made for alone. The page checks that before storing it.
    • It's sealed, then kept by GitHub. Your browser encrypts it with the course repository's public key. It's stored as that repository's secret ORG_ADMIN_TOKEN. From then on only that repository's workflows can read it: not this page, not other repositories, not even you on GitHub.
    • It can do only what the bot does. Every permission is listed below.
    • It lasts as long as your term. When it runs out the bot stops, your course's page tells you, and you replace it there.
    • It acts as whoever makes it, who must own . A separate GitHub account just for the bot, made an owner, keeps the bot's actions apart from yours.
